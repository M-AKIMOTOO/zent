# DRGスケジュールから転送スクリプトを生成

`mkzent.py` は、DRGの `$SKED` と記録ログの
`$REQRECSTART` からスキャンごとのバイト範囲を計算します。送信側・受信側の
シェルスクリプトと、計算結果のTSV一覧を生成します。受信スクリプトは既定で
受信先の `--odir` に `scp` で転送します。観測データの転送は開始しません。
既存のローカル生成ファイルは、`--force` を指定しない限り上書きしません。

`--drg` を省略すると、`--ifile` のファイル全体を元のファイル名で転送する
スクリプトを生成します。この場合、ログ、`--recstart`、`--ant` は不要です。
入力は空でない通常ファイルで、生成時のファイルサイズが転送直前にも一致する
必要があります。転送終了まで入力ファイルを変更しないでください。

```bash
mkzent.py --ifile /data/input.vdif --corr 1 --port 9002 --odir /data/raw
```

ファイル全体を転送する場合、manifestの `duration_sec` は `-` です。転送を
正確なバイト数で指定するため、生成される送信コマンドは `--bs 1` を使用します。

実行にはPython 2.6以降またはPython 3が必要です。RHEL 6のPython 2.6で
動作する構文を使用していますが、RHEL 6実機ではまだ確認していません。

## 準備と生成

両方のマシンにこの版のソースを配置し、それぞれのマシンでビルドしてください。
生成スクリプトは `--length` が秒単位の新しい `zent` を使用します。以前生成した
送信スクリプトは使用せず、`mkzent.py` で送受信の両方を生成し直してください。
異なる環境で作った `.o` や実行ファイルを使い回さず、次を実行します。

```bash
make clean
make
make install
```

`make install` は `zent` と `mkzent.py` を `~/bin` に配置します。別の場所に
配置する場合は `make install BINDIR=/path/to/bin` を使います。

例：送信側で生成します。`--drg`、`--log`、`--ifile`、`--odir` は
実際の環境に合わせてください。接続先は `--host` または `--corr` の
どちらか一方を指定すれば、送受信の両方に同じIPv4アドレスが使われます。

```bash
python mkzent.py \
  --drg I26274X.DRG \
  --log u26274x_ch1_ymg34xl.log \
  --ifile /mnt/raid/u26274x_ch1_ymg34xl.vdif \
  --corr 1 --port 9002 \
  --odir /data/raw --ant 1
```

`--corr` の対応は、1、2、3、5、6、8が `corrN_10G`、44が `Rocky`、
101が `yamaNAS1` です。`mkzent.py` を実行する送信側でホスト名をIPv4アドレスに
解決し、そのアドレスを送信側・受信側の両方のスクリプトに設定します。受信側で
ホスト名を解決する必要はありませんが、そのIPは受信側に設定されている必要が
あります。DNSの設定を変更した場合はスクリプトを生成し直してください。
スクリプトのコピーにはSSH/scpを使います。観測データ本体は直接TCPで転送します。
待ち受け先だけ別にしたい場合、または生成時に名前解決できない場合は `--bind`
で指定できます。その場合、送信スクリプトは接続先ホスト名を使用します。

`--ant 0` は `YAMAGU32` / K、`--ant 1` は `YAMAGU34` / L です。アンテナは
出力名に使い、DRGの局欄に基づくスキャンの絞り込みは行いません。ログは以下の形式で、
`$REQRECSTART` がちょうど1行必要です。時刻はUTCです。

```text
$REQRECSTART 2026275215500
```

生成されるファイル名は、入力VDIFの拡張子を除いた名前に基づきます。

```text
zent_<入力名>_send.sh
zent_<入力名>_recv.sh
zent_<入力名>_run.sh
zent_<入力名>_manifest.tsv
```

受信スクリプトは `--host`／`--corr` で指定したホストの `--odir` にコピーします。
受信先のディレクトリは事前に作成しておいてください。同名のリモートスクリプトは
上書きされます。scpの認証はSSHの設定を使用し、必要に応じてパスワードを入力します。
コピーに失敗した場合はエラー終了しますが、ローカルの生成ファイルは残ります。
ローカル生成だけを行うには `--no-deploy` を付けてください。

scpを使用する場合、ホスト名と `--odir` は半角英数字・`_`・`-`・`.`、
ディレクトリでは加えて `/`・`+` を使用できます。空白などを含む場合は
`--no-deploy` で生成後、手動でコピーしてください。

`--out-prefix` でローカルの生成先・接頭辞を変更できます。`--odir` が相対パスの
場合、scp時は受信側のホームディレクトリからの相対パスで、そのディレクトリに
スクリプトと受信ファイルを置きます。`--no-deploy` の場合は受信スクリプトの
置き場所からの相対パスです。送信ファイルは生成時に絶対パスに変換します。

同じ名前のスクリプトを再生成するには、前回のコマンドに `--force` を追加します。
ローカルの送信・受信・一括実行スクリプトとmanifestを上書きし、通常どおり受信側にもscpで
転送します。既存の内容を残したい場合は、代わりに別の `--out-prefix` を指定します。
`--force` は通常ファイル以外を上書きしません。

## 転送

送信側・受信側に更新版をインストールしたら、送信側で生成された `_run.sh`
を実行すると、受信側をSSHで起動し、待ち受けを確認してから送信します。
受信側を別端末で起動する必要はありません。選択した総スキャン数・総バイト数と
完了スキャン数を表示します。

```bash
./zent_..._run.sh
# バイナリの場所や受信設定を指定する場合
ZENT=/local/bin/zent REMOTE_ZENT=/remote/bin/zent \
  RECEIVE_MODE=rw WRITE_BATCH_MIB=4 ./zent_..._run.sh
```

`make install` は `zent-run` と `zent-bench` も配置します。`zent-run` がPATHに
ない場合は `ZENT_RUN=/path/to/zent-run` を指定します。SSHの接続先は元の
`--host`／`--corr` 名で、SSH設定と認証を使用します。データ本体は直接TCPで
流れます。リモートではbash・setsid・zentが必要です。`REMOTE_ZENT` を省略
すると、リモートのPATH上のzent、なければ `~/bin/zent` を使います。

一括実行は、その時点のローカル受信スクリプトをSSH経由で実行するため、
`--no-deploy` で生成した組にも使えます。相対 `--odir` は受信側のホームからの
相対パスです。手動でローカル受信スクリプトを起動する場合の基準とは異なります。

一括実行は両側の進捗を表示し、送信スクリプトの隣に時刻とPID付きのログを
作成します。`./zent_..._run.sh --log transfer.log` で保存先を変えられます。
既存ログは上書きしません。受信の起動待ちは既定60秒で、`--ready-timeout 300`
のように変更できます。中断や送信失敗時は、この実行で起動した受信プロセス群を
終了させます。NFS/ディスク処理が割り込み不能な場合は終了が遅れることがあります。
再開モードの部分ファイルと状態は保持します。

手動で実行する場合は、次のように両側を起動します。

受信側で先に起動し、待ち受けメッセージを確認してから送信側で起動します。
以下の `...` は生成された実際のスクリプト名に置き換えてください。
`ZENT` には、それぞれのマシンの実行ファイルを指定します。

```bash
# 受信側
ZENT=/path/to/zent bash ./zent_..._recv.sh

# 送信側
ZENT=/path/to/zent bash ./zent_..._send.sh
```

スキャンごとに1接続し、受信側に `YAMAGU34_2026274064200.raw` のような
ファイルを作ります。転送失敗時は両スクリプトともそこで停止します。受信側の
待ち受け切り替え時に接続が拒否された場合、送信側は接続前に限り1秒間隔で
30回まで再試行します。`RETRIES=60` のように変更できます。

### 途中再開を有効にする

生成時に `--resume` を追加すると、両スクリプトで途中再開を有効にします。
送信側・受信側の `zent` を両方更新し、同じ組のスクリプトを使ってください。

```bash
mkzent.py --ifile /data/input.vdif --corr 8 --port 9002 \
  --odir /mnt/corr8_10G/raw --resume
```

通信切断時は既定で3回まで再接続を試みます。両側が終了した場合は、同じ
受信・送信スクリプトを先頭から再実行できます。状態が一致する完了スキャンは
データを再送せず、未完了スキャンは同期済みの位置から送ります。既存ファイルを
サイズだけで完了扱いにはしません。以前の版で作った出力に照合用の状態がない
場合や、送信元・転送範囲が変わった場合は停止します。

受信先には `.zent.part`、`.zent.state`、`.zent.lock` ができます。完了後も
状態とロックファイルは残します。再開には必要なので編集・移動・削除せず、
受信実行中にロックファイルを削除しないでください。再開時は同じ受信ホストと
マウントを使います。送信元はホスト・絶対パス・inode・サイズ・mtime/ctime・範囲を
照合するため、観測中で増え続けるファイルには `--resume` を使わないでください。
内容のハッシュ検証は行いません。

両側の `TRANSFER_RETRIES=5`、`IDLE_TIMEOUT=300` で再接続回数・待ち秒数を
変更できます。初回の受信待ちは無期限です。タイムアウトはソケット待ちに適用し、
NFS/ディスクの書き込みや同期時間を制限するものではありません。完了応答が失われ、
送受信スキャンの位置がずれた場合も、両側を終了して同じ組を先頭から再実行します。

受信側の `CHECKPOINT_MIB=256` で同期・再開位置の保存間隔を指定できます。
小さくすると強制終了時の再送量が減り、同期の負担は増えます。再開モードでは
完了時にも同期します。親ディレクトリは同期しないため、電源断時の永続性を
保証する機能ではありません。

受信方式を比較するには、受信スクリプトの実行時に次を指定できます。

```bash
RECEIVE_MODE=rw WRITE_BATCH_MIB=4 bash ./zent_..._recv.sh
# または splice のパイプ拡大を要求（OSが許可した範囲で使用）
PIPE_MIB=1 bash ./zent_..._recv.sh
```

既定の受信方式は従来のままです。NFSやディスクの条件で効果が変わるため、
同じ範囲・負荷で比較してください。進捗には直近速度とペイロードの残り時間を
表示します。再開済み部分は速度計算から除き、最終の保存待ちは別メッセージに
表示します。スキャン全体の合計ETAではありません。

PC2からNFS受信先への書き込み方式を比較するには、PC2上の変更されない
ローカルファイルを指定して `zent-bench` を実行できます。

```bash
zent-bench --input /local/stable.raw --directory /mnt/corr8_10G \
  --length 268435456 --runs 3 --csv receiver.csv
```

既定の5方式を各3回、毎回指定量だけ転送し、同期完了と内容のSHA-256一致を
確認します。既定の範囲は先頭から最大256MiBです。`--offset`・`--length` は
バイト単位で、指定範囲を正確に使います。ハッシュ計算を測定時間から除き、
事前に送信範囲を一度読みます。計測用の出力だけを専用の一時ディレクトリに
作成・削除し、入力や既存出力は変更しません。方式数×回数ぶん書き込むため、
観測・相関処理との負荷共有を考慮して実行してください。`--resume` を付けると
再開用の同期負荷も含めます。`--cases splice,rw` で比較する方式を絞れます。
PC1→PC2のネットワークを測るコマンドではなく、PC2の受信・保存経路の比較です。

同じ受信側IPとポートでは同時に複数の受信処理を起動できません。受信中も
ポートを保持し、競合した受信側は `Port conflict` を表示して終了します。
指定できるポートは 9000〜9010 です。
複数チャンネルを同時転送する場合は、それぞれ異なる `--port` を指定して
スクリプトを生成し、送信側と受信側で対応する組を使用してください。連続実行する
場合は、前の受信処理が終了してから同じポートを再利用できます。

相関処理とRAIDを共有する場合は、送信側の速度を抑えて影響を確認できます。
既に生成した送信スクリプトでも、新しい `zent` をインストール後、環境変数で
1プロセスあたりの送信上限を指定できます（例: 約100 MiB/s）。

```bash
ZENT_RATE_MIB=100 ./zent_..._send.sh
```

生成時に `mkzent.py --rate-mib 100 ...` と指定して既定値にすることもできます。
`0` は無制限です。指定は送信速度の上限の目安であり、受信側のページキャッシュの
書き戻しや複数送信を含むディスク負荷を厳密に制限するものではありません。相関の
進行と `iostat -xm 1` を見ながら実機で調整してください。`--bs` は記録データの
1秒あたりのバイト数で、送信速度の上限とは別です。

`--resume` を使っていない場合、途中で失敗したら両側を停止し、完成ファイルを確認してください。ACKが
失われた場合、送信側が失敗していても受信ファイルが完成している場合があります。
スキャンを除外して再開する場合は、同じ `--exclude-scan` を指定して新しい
接頭辞で**両方のスクリプトを生成し直し**、両側で同じ組を使用してください。
既存の受信ファイルは上書きしません。

## 範囲計算とオプション

```text
offset = file-offset + (scan開始UTC - REQRECSTART) × data-rate
length = scan継続秒数 × data-rate
```

既定の `--bs`（`--data-rate` も指定可能）は **256000000 byte/s**、
`--file-offset` は0です。対象のファイルが、このレートで欠落なく連続記録され、
`REQRECSTART` がファイルの対応する位置を表すことが前提です。VDIFのフレームや
記録の欠落を自動解析しません。正しいレート、先頭位置、記録開始時刻を確認し、
まずmanifestを確認してください。必要なら次を指定できます。

- `--bs BYTES`（`--data-rate` は別名）: 記録データの毎秒バイト数。
- `--rate-mib N`: 送信速度の上限をMiB/秒で指定（既定は0、無制限）。
- `--resume`: 途中再開と照合済みの完了ファイル再利用を両スクリプトで有効にする。
- `--file-offset BYTES`: 記録開始時刻に対応するファイル内のバイト位置。
- `--recstart YYDDDhhmmss`: ログの代わりに開始UTCを指定。4桁年も使用可能。
- `--exclude-scan 2,5-7`: DRG順のスキャン番号を除外。繰り返し指定可能。
- `--exclude-target NAME,NAME`: 天体名を除外。大文字・小文字を区別しません。
- `--no-deploy`: scpを行わず、ローカルにファイルを生成するだけにします。
- `--force`: 同名のローカル生成ファイルを明示的に上書きします。

`--log` と `--recstart` はどちらか一方を指定します。スキャン開始が記録開始より
前の場合や、範囲が64ビット上限を超える場合は生成を中止します。実ファイルの
範囲外でないことは、各転送時に `zent --send` が検証します。
